使用指南

快速掌握 TeamFlow Wiki 的核心协作工作流：

1

模块化块级编辑

点击任意文本块即可直接编辑，按 Enter 键换行。每一行都是独立积木，可自由修改。

2

斜杠命令 (Slash Command)

在新行输入 / 即可呼出快捷菜单，一键插入标题、分隔线、图片或普通段落。

3

拖拽手柄排序

悬停于每一行左侧可显现 ⠿ 手柄，长按即可上下拖拽块重新排布内容顺序。

4

GitHub 自动云同步

在设置 (⚙️) 中输入 GitHub Token 及仓库信息后，即可免安装 Git，一键向远端推送更新。

🔄

云端协作配置向导

只需 3 步，即可在团队中建立共同的 GitHub 云端数据同步闭环，实现免安装协同：

1

1. 共同建库

团队主导者在 GitHub 上新建仓库（推荐初始化 README.md），并在 Settings -> Collaborators 中将团队成员添加为协作者（私有库必须），使大家获得写入权限。

2

2. 创建 Access Token

每个成员在个人 GitHub 设置中生成 Token。Classic 令牌需勾选 repo 权限；Fine-grained 令牌需授予该仓库 Contents 属性的 Read and write 读写权限。

3

3. 同步配置与提交

进入 Wiki 点击 ⚙️ 设置，填入相同的 Owner、Repo 与个人的 Token 保存。点击顶部“同步到 GitHub”，即可推送本地修改并实时拉取同步，完成闭环！

⚠️ 常见错误与故障排查

可能原因：仓库所有者 (Owner) 或仓库名称 (Repo) 拼写错误；或者 Token 没有访问该仓库的权限；或者协作者尚未接受仓库的合作邀请。
解决方案：仔细核对 Owner 和 Repo 拼写；检查 Token 作用范围是否包含该仓库；协作者需先访问 https://github.com/用户名/仓库名/invitations 接受邀请。

可能原因：输入的 Personal Access Token（个人访问令牌）不正确、已失效或已过期。
解决方案：前往 GitHub 开发者设置重新生成 Token，复制并完整填入，确保没有复制多余的空格或换行符。

可能原因：Token 校验成功但没有写入权限（Classic 令牌未勾选 repo，或 Fine-grained 令牌未在 Contents 中赋予 Read and write）；或者主分支设置了分支保护规则，阻止了直接推送。
解决方案：在 GitHub 修改该 Token 的权限，确保选中 repo 写入或 Contents 读写；或在仓库设置中暂时调整分支保护规则。

可能原因：本地网络访问 GitHub API 失败或超时；或者是 SSL 证书验证在部分本地中继代理中出错。
解决方案：检查本地网络。如果使用了代理客户端，请确保其处于全局/规则代理状态并能正常连通 api.github.com；或参考文档调整 BepInEx/代理配置文件。
